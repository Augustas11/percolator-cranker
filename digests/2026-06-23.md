## 1. 🔔 Cranker-enabling signal

### 1d — The reference cranker entry point now exists, singular and public

Commit **`f5f45dc`** ("Expose one public permissionless crank (the auto-crank);
internalize the direct crank", Anatoly, 2026-06-18) is the headline. It
restructures the public crank surface to exactly **one** entry point:

- `pub fn permissionless_auto_crank_not_atomic(&mut self, account, work: AutoCrankWorkV16) -> V16Result<AutoCrankResultV16>` — `src/v16.rs:11298`.
- The previous caller-chosen-action entry point `permissionless_crank_not_atomic`
  (the baseline cranker hook, `bbe745a:src/v16.rs:10373`) was **demoted to
  `pub(crate)`** — it is now an internal dispatch primitive, no longer a wrapper
  entrypoint.

**Mechanism (from the code, not the message):** the caller submits authenticated
oracle **observations** (asset, price, funding) plus a liquidation budget; the
**engine** — not the caller — builds an actionable summary
(`build_actionable_summary`), selects the highest-priority step *and its asset*
from current on-chain state via the proven selector `select_auto_crank_plan`
(`src/v16.rs:1210`), and dispatches exactly one bounded primitive. One
instruction = one step (no loop to fixed point). A step whose observation is
absent returns `NonProgress` with **no mutation**, so a stale/late tx is a clean
no-op under SVM rollback and arbitrary landing order is safe.

This is the operational template the watch thesis is built around: whoever
ships the reference cranker against this surface sets the template. **It is now
fully specified.** Crank references across `src/` + `spec.md` jumped **31 → 110**.

The engine-selectable plan (`AutoCrankPlanV16`, `src/v16.rs:4443`) enumerates
every action a cranker can drive:

```
NoAction
RefreshAccount { asset_index: Option<usize> }
SettleBChunk   { asset_index: usize }
Liquidate      { asset_index: usize }
DeclareRecovery{ reason: PermissionlessRecoveryReasonV16 }
CloseResolved
```

Supporting type family landed across `2e7017f`, `e903491`, `1463dc0`,
`806ddfd`, `9c084c4`, `4329756`, `9e939cb`, `485e804`, `65e136c`:
`AutoCrankObservationV16`, `AutoCrankWorkV16`, `AutoCrankPlanV16`,
`AutoCrankOutcomeV16`, `AutoCrankResultV16` (all `pub`, exported in
`src/lib.rs:56–65`).

**The README now ships the cranker integration guide** —
`README.md:159` "### Permissionless crank: one public route":
> Wrapper call: decode the instruction → authenticate clock/observations →
> build `AutoCrankWorkV16` → call once → mirror token/custody movement keyed off
> `result.selected` (`AutoCrankPlanV16`).

This is the closest the repo has come to a deployable cranker contract.

## 2. 🚦 Partial green light — the deployment-surface CODE is public (NOT deployed)

This is the section the whole watch exists to produce. Multiple green-light

chain.** A reference cranker can be *drafted* against it; there is nothing live

### 2.2 Why it is a green light (every trigger, fired)

- **🚦 Sibling wrapper / reference-program repo.** `percolator-prog` README:
  *"Percolator is a Solana program that wraps the `percolator` crate's v16
  account-local risk engine and exposes a composable instruction set for
  deploying and operating perpetual markets."* This is the deployment surface,
  by its own description.
- **🚦 Program id.** `src/v16_program.rs:32` —
  `declare_id!("Perco1ator111111111111111111111111111111111")`. A concrete
  on-chain program id, the exact thing the upstream library refuses to define.
- **🚦 Chain target.** Solana, explicitly — `solana_program`, PDAs, CPI matcher
  model, SPL-token vault, BPF compute-unit regression tests (`tests/v16_cu.rs`,
  `v16_bpf_*`).
- **🚦 Crank economics defined.** `src/v16_program.rs:520-521` market config:
  `liquidation_cranker_fee_share_bps: u16` and `maintenance_cranker_fee_share_bps:
  u16` (both validated ≤ 10_000). README §Operational runbook:
  - Liquidation reward: when `liquidation_cranker_fee_share_bps > 0`, the keeper
    *"may append its writable Percolator portfolio account as the final account
    in the instruction"* to receive the retained liquidation penalty share; omit
    it and the penalty stays in insurance.
  - Maintenance reward: an optional final writable cranker portfolio receives
    `maintenance_cranker_fee_share_bps` of the fee as internal account capital.
  This answers who-pays-the-cranker / in-what-asset / on-what-trigger — the
  crank-payment schedule the watch was waiting for. Paid in collateral atoms,
  internalized to the cranker's own Percolator portfolio, per liquidation /
  maintenance event.

### 2.3 The deployed reference-cranker hookpoint

`src/v16_program.rs` implements the crank as a first-class instruction:
`Instruction::PermissionlessCrank { now_slot, close_q, observations }` →
`handle_permissionless_crank(...)` (dispatch at `:5153`). The caller submits up
to 16 authenticated `CrankObservationHint`s (asset, price, funding — the
worst-known stale/bankrupt/liquidatable accounts as untrusted hints) plus a
budget; the engine selects the action+asset and makes cursored progress
regardless of hint quality. **This is the concrete target a reference cranker
bot drives.** The watch thesis — "whoever ships the reference cranker against
the first deployed wrapper sets the operational template" — now has its wrapper.

### 2.4 What is NOT launched (verified, not assumed)

- **The program is NOT deployed on any chain.** Direct `getAccountInfo` calls
  against the declared id on both mainnet-beta and devnet returned
  `value: null` (verified 2026-06-23). The account doesn't exist on-chain.
- **The program id is a vanity placeholder.** `Perco1ator111111111111111111111111111111111`
  — the trailing `1`s are base58 zero-padding (only the first 10 bytes carry
  the "Perco1ator" pattern, the rest is zeros). Real program ids are 32 bytes
  of randomness or a vanity prefix with non-zero suffix. This is a development
  stand-in waiting to be replaced.
- **Unaudited and explicitly disclaimed.** README banner: *"FOR EDUCATIONAL
  PURPOSES ONLY. This code has NOT been audited. Do NOT use in production or
  with real funds. This is experimental software provided for learning and
  testing purposes only."*
- **No release tag, no announcement.** No git tags on `percolator-prog`; no
  launch post locatable from the repo.
- **No live markets, no live keepers, no on-chain activity** — the wrapper has
  no chain on which to have activity.
