## 1. 🔔 Cranker-enabling signal

No NEW crank surface landed on `master` (static). But three ready PRs opened
**today (2026-07-10)** are all refinements to the **existing permissionless
auto-crank dispatch** (`select_auto_crank_plan` / `AutoCrankPlanV16`), and each

For a cranker builder these enumerate the exact failure modes a naive keeper hits:

- **PR #98 — Skip Recovery legs in auto-crank action selection** (aeyakovenko/codex,
  branch `codex/fix-recovery-first-autocrank`, READY). Bug: the self-classifying
  crank picked the *first active portfolio leg* without checking asset lifecycle.
  In a mixed portfolio where leg 0's asset was shut to `Recovery` and leg 1 was
  live, both stale-refresh and liquidation targeted the Recovery asset → every
  dispatch rejected with `LockActive`, and every retry re-selected it (a
  permanent stall). Fix: filter ordinary active candidates against production
  lifecycle, select first `Active`/`DrainOnly` leg; the `liquidatable` signal now
  requires ≥1 dispatchable leg. New regression
  `v16_auto_crank_skips_recovery_first_leg_for_live_refresh`. Touches
  `src/v16.rs` + `tests/v16_spec_tests.rs`.
  → **Cranker takeaway:** the reference crank could livelock on
  `LockActive` before this. A keeper must not treat a returned plan as
  dispatchable purely because a leg is "active."

- **PR #99 — Make prior-reset auto-crank obligations progress** (aeyakovenko/codex,
  branch `codex/fix-resetpending-autocrank`, READY, **stacked on #98**). A public
  liquidation can strip all effective OI from the winning side and leave the
  counterparty a prior-epoch `ResetPending` obligation that sorts *before* a
  genuinely liquidatable live leg → crank returns `InvalidLeg` forever unless the
  *owner* invokes the explicit forfeit route (absent owner ⇒ permanent block).
  Fix: classify a prior-epoch `ResetPending` leg as an explicit refresh/cleanup
  task, settle its K/F/B state, then detach **at most one inert obligation per
  bounded refresh call** (CU-bounded), keeping refresh and liquidation candidate
  scans separate. Touches `src/v16.rs` + `tests/v16_spec_tests.rs`.
  → **Cranker takeaway:** confirms the crank must make owner-independent progress
  on stranded obligations — directly relevant to the "permissionless liveness"
  guarantee a service operator sells.

- **PR #100 — Keep partially ADL-reduced positions exit-live** (aeyakovenko/codex,
  branch `codex/fix-adl-exit-progress`, READY). A public partial liquidation can
  ADL a winning side so the account holds two stored-basis lots while the market
  has one lot of matched effective OI → keeper hits `CounterUnderflow`; reducing
  one lot leaves a nonzero `Normal` leg that every later reduction fails on, with
  no reset cleanup actionable. Fix: cap unilateral liquidation/rebalance work by
  *matched effective OI*; on exhaustion enter the existing reset epoch; migrate
  legacy `Normal` zero-effective-OI residues so an **unsigned auto-crank** settles
  terminal K/F/B and detaches them (never while a loss barrier / pending
  obligation owns the side). Touches `src/v16.rs` + `tests/v16_spec_tests.rs`.
  → **Cranker takeaway:** a third distinct "wrong-leg / dead-leg" stall class.

**Pattern:** all three are the same theme — the permissionless auto-crank's

producing deterministic stalls (`LockActive` / `InvalidLeg` / `CounterUnderflow`)
that only an owner action could clear. The reference crank's **liveness contract
is being closed PR-by-PR this week.** None merged yet (master static). See
