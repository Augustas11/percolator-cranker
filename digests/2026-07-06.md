- Commits: `43302e6` "Fix liquidation min-fee chunking" · `52b0286` "Make
  liquidation size engine-selected" · `a3e0357` "Compute minimum liquidation
  close size". Touches `src/v16.rs` (+244/-…), `src/v16_kani_api.rs` (+46),
  `tests/proofs_v16.rs` (+155), `tests/v16_spec_tests.rs` (+170).
- **Mechanism (not paraphrase):** the public auto-crank work struct loses its
  caller-supplied work budget. On master:
  ```
  pub struct AutoCrankWorkV16<'a> {   pub struct LiquidationRequestV16 {
      pub now_slot: u64,                  pub asset_index: usize,
      pub observations: &[…],             pub close_q: u128,   // ← removed
      pub liquidation_max_close_q: u128,  // ← removed   pub fee_bps: u64,
      pub resolved_close_fee_rate…    }
  }
  ```
  Post-PR, the doc comment reads: *"NO caller-chosen action, asset, liquidation
  **size**, or liquidation fee — the engine selects the step/asset, closes the
  selected leg, and derives the fee from config."* The keeper now submits only
  observations + the resolved-close fee rate; the engine computes the **minimum**
  close size that restores maintenance health (`liquidation_engine_close_request_q`,
  `liquidation_projected_healthy_after_close`, `liquidation_leg_maintenance_requirement`
  — all new private fns) and derives the fee via `liquidation_fee_for_close`
  (`min_liquidation_abs`/`liquidation_fee_cap` clamps, with a no-min-fee carve-out
  when the leg is fully closed).
- **Why it matters:** this is the auto-crank contract getting *strictly more
  order-insensitive* — the cranker's job shrinks (no size math, no fee choice;
  just push fresh observations and a budget-free liquidation step). It is the
  direct continuation of the 2026-06-26 no-observation-progress relaxation. For
  the reference-cranker thesis it is favorable (thinner client), **but it changes
  the instruction surface** the wrapper exposes — see §9.
- **No new `cfg_*_chunks` knob** (baseline set unchanged: `cfg_max_account_b_
  settlement_chunks`, `cfg_max_bankrupt_close_chunks`, `cfg_pending_obligation_
  settlement_chunks`, `cfg_public_b_chunk`). **No new `*Phase` enum. No new
  `pub fn`.** The removed fields are the notable surface change. Confidence:
  MEDIUM (draft, unmerged — could still be reworked before landing).
