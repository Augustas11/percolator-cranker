## 1. 🔔 Cranker-enabling signal

**The keeper is out of the liquidation-sizing business — observation-only crank
is now canonical on both engine and wrapper.**

- **Engine — PR [#92](https://github.com/aeyakovenko/percolator/pull/92)
  (`b97e174` "[codex] Fix liquidation min-fee chunking", merged 2026-07-10
  17:22Z).** `LiquidationRequestV16` went from
  `{ asset_index, close_q, fee_bps }` (at last-run `68986f7`) to
  `{ asset_index }` only (`src/v16.rs:5404`). The engine now derives close size
  via `liquidation_engine_close_request_q` (`src/v16.rs:497`) and the fee via
  `liquidation_fee_for_close` (`src/v16.rs:16408`); `liquidation_max_close_q` is
  gone entirely. `PermissionlessCrankActionV16::Liquidate(LiquidationRequestV16 {
  asset_index })` (`src/v16.rs:11834`) confirms the crank action now carries only
  the asset index.
- **Wrapper — PR #206 (`970ddc5` "Remove keeper-controlled liquidation sizing",
  merged 2026-07-10 19:30Z on `percolator-prog`).** Removed `close_q: u128` from
  the `PermissionlessCrank` variant (`src/v16_program.rs:2447`) **and** from the
  wire codec: the decoder no longer `read_u128`s a close_q for tag 5, and the
  encoder no longer `push_u128`s it. New tag-5 layout:
  `[5][now_slot:u64][n:u8][n × (asset_index:u16, oracle_accounts:u8)]`.

**Why this is a cranker signal, not just a fix:** it removes a keeper input from
the reference crank's submission entirely. A cranker no longer chooses *how much*
to liquidate or *what fee* to charge — it supplies only observation hints and the
engine picks the minimum health-restoring close. This *simplifies* the reference
cranker and hard-locks the "keeper supplies oracle accounts, engine decides
everything else" model that prep.md already identified as the design's spine.
See §9 for the wrapper-client break this creates.

PRs, #98–#120).** aeyakovenko has a large in-flight batch, all bounding CU and
preserving liveness of the *existing* `permissionless_auto_crank_not_atomic`
surface (`src/v16.rs:11734`) — no NEW crank operation, no new `cfg_max_*_chunks`
knob, no new `pub fn crank_*`. This is operator-side reliability hardening of the
