## 1. 🔔 Cranker-enabling signal

**PR #173 — "[PARTIAL DoS] Make lapsed live source backing publicly progress"**
(aeyakovenko, DRAFT, opened 2026-08-06T06:08Z, branch
`codex/pr135-live-expiry-engine-20260805`, base `master`).
Signal types **1d** (new crank-shaped progress path) + **1b-adjacent** (new outcome
enum variant on the crank state machine) + **1a-adjacent** (bounded by a per-call cap).

Mechanism (verified against branch diff, not commit-message paraphrase —
`src/v16.rs`, +166/−0 net in that file):

- **New crank outcome variant.** `PermissionlessProgressOutcomeV16` on
  `origin/master` has 4 variants (`AccountCurrent`, `AccountBChunk`,
  `ResidualBooked`, `RecoveryDeclared`). The branch adds a 5th:
  `SourceBackingExpired { domain: usize }`
  (`git show origin/codex/pr135-live-expiry-engine-20260805:src/v16.rs`). Confirmed
  `SourceBackingExpired` count on master = **0**.
- **New internal machinery** (all `not_atomic`, driven from the existing public
  `permissionless_auto_crank_not_atomic` entry — *no new `pub fn`*):
  `kernel_lapsed_source_backing_scan_step`, `first_lapsed_source_backing_for_account`,
  `expire_first_lapsed_source_backing_for_account_not_atomic`, and a new
  `AccountRefreshCertOutcomeV16::SourceBackingExpired(usize)` cert arm.
- **Per-call bound.** The scan is capped by `PORTFOLIO_SOURCE_DOMAIN_CAP`
  (`src/v16.rs:22` — `= 2 * V16_MAX_PORTFOLIO_ASSETS_N`; Kani cfg = 4). Comment in
  the diff: *"The permissionless path commits exactly one canonical expiry
  transition per call, then returns before valuation. Repeated auto-cranks drain
  the … set."* This is the classic crank-drains-a-finite-set liveness shape.
- **Why it matters operationally.** Root cause (from PR body, corroborated by the
  diff): a funded live portfolio with positive PnL sourced from a backing bucket
  could outlive that bucket's expiry; the sole public auto-crank then hit valuation
  with stale backing and returned `Stale` with no public transition to normalize
  the dependency — leaving the owner's risk-reduction path unavailable absent a
  privileged update. The fix makes that stale dependency itself a permissionless
  bounded continuation. **A cranker must handle this new progress outcome** (it is
  a new "work available / progress made" signal the bot can act on and, if it does
  fee-share collection, potentially earn on).
